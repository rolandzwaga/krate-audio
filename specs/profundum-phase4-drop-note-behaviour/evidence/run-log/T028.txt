=== 4. Diagnosis and decision needed ===
- In the composition, the per-sample cost is 14.8-17.6 ns/sample. The T005 kernel bench (plan S10.7) measured
  5.7-7.2 ns/sample for term A. That is 2-3x the bench figure. The solve term is small next to this: one solve per
  100 ms at about 10 us is about 0.01 %. So the overrun comes from the per-sample path (envelope, lock + mirror,
  Quantized glide, declick, NoteMemory, MonoHandler in the test Voice), not from the trigger solve.
- T018.txt still records SC-019 as NOT MEASURED. This is the first measurement of the composed case.
- T018's lever rule says "apply the next unused R-1 lever in the headers". The 2026-10-12 ruling already made levers
  (2) and (3) and both per-sample reductions REQUIRED, and lever (4) is conditional. That leaves no unused R-1 lever
  that touches the per-sample term A. T028's file list is this log only, so no header edit was made here.
- Decision for the main loop / user: how to recover the ~0.02-0.035 % per-sample overrun at a fixed 0.05 % bar.
  Options:
  (a) profile the Voice in drop_note_behaviour_perf_test.cpp per component to find which piece costs 2-3x its bench
      figure. Also check whether the test Voice itself adds per-sample overhead that is not Phase 4 cost (e.g. MonoHandler
      per-sample work outside the Phase 4 glide addition);
  (b) authorise new per-sample levers in drop_envelope.h / drop_phase_lock.h / mono_handler.h beyond R-1;
  (c) a scope ruling on what SC-019 counts.
  Relaxing the bar is not an option under R-1/C-16.
