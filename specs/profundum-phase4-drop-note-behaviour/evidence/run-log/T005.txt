=== 1. Bench ===
Source: specs/profundum-phase4-drop-note-behaviour/bench/drop-kernel-bench.cpp (stdlib only, no repo header).
Prototypes: DropCurve + makeDropCurve (S3.1-S3.5, C-12 constants, snap and bridged; O-1 ruling: rise L_r = L_min,
no sigma_up), integrate = GL8 fixed panels (2 per piece, 4 on pieces > 0.5 N, constexpr node array);
DropEnvelope S3.4 kernel (uint32 counter, one geometric recurrence per exponential term seeded with std::exp at the
piece entry, Horner on Hermite pieces, float out) as processBlock; DropPhaseLock S5.2 correction (Horner b, one add,
float cast, bridged carry Hermite) + S5.6 mirror (exp2 once per 16 samples, one add per sample) as processBlock;
MonoHandler Quantized law S4.2 (counter-based, pow only on a step change; T009: no sigma_up floor), per sample;
RetriggerDeclick C-15 (double rotation, switch sample 0.0f) as processBlock; S5.3 predictor (hold term + 4 exact
updates + GL8 integral from t4 + EM endpoint terms, analytic dPhi/dgamma) and S5.4 solve (gamma_lim = 48 per the
O-1 ruling; 1 shared + per candidate 2 bracket + 6 Newton/bisection).
Configurations (48 kHz, host block 64):
  (A) per-sample load: Drop s = 1, R = 1, A = 24, T = 200 ms snap-retriggered every 100 ms (curve rebuilt each
      time) + correction + mirror + Quantized glide 24 st / 500 ms restarted every 1 s + declick armed every 100 ms.
      4 s of audio per trial, median of 9 trials.
  (B) worst-case trigger + solve: bridged, T = 1 ms, A = 48, s = 1, R = 1, from mid-fall (u = 0.5) of a T = 20 ms
      drop with a running correction (gamma_prev 2.5) carried; 11 pieces (brake 48 + rise 48 samples), 24 GL8
      panels per evaluation integrated from t4 (192 nodes + 6 point nodes); evaluations forced to the cap
      (17 at stages 0-2; 9 at stage 3, see lever (4)); curve build included. 2000 solves per trial, median of 9.
  (C) typical trigger + solve: snap, A = 24, T = 200 ms, s = 1/3, R = 0; natural early stop at 1e-9 cycles.
  Solve sanity (every stage): B Phi_hat(0) = 1.789019 cycles, n* = 2, gamma = 2.950657 st, residual <= 1.3e-15
  cycles, feasible; C gamma = 0.729305 st, residual ~1e-13.
Stages = plan S13 R-1 levers applied cumulatively in order:
  0 plain; 1 + (2) hoisted Hermite coefficients; 2 + (3) cached 2^{(d+carry)/12} and b per node, each pass
  multiplies by 2^{gamma b/12}; 3 + (4) linearised start (Newton from gamma_0 = (n* - Phi(0))/Phi'(0), no
  bracket-end passes, 4 passes per candidate => worst case 1 + 2 x 4 = 9 evaluations).
  Lever (1) (idle fast path) cannot move (A): the envelope is never idle under the 100 ms retrigger. Lever (5) (lazy
  solve) is already in S5.4.

=== 4. Decision ===
- Plain S5.4 solve: median F 0.0722 % > 0.05 % bar -> NOT adopted.
- Lever (2): 0.0708 %. Lever (2)+(3): 0.0399 %. Lever (2)+(3)+(4): 0.0433 % (A noise: the A code is identical in
  stages 1-3; the solve term itself falls 0.0370 % -> 0.0123 % -> 0.0085 %).
- No stage reaches the 0.033 % target (two-thirds of the bar, MSVC headroom). Every stage after lever (3) sits
  between the 0.033 % target and the 0.05 % bar, so the task's stop clause (F > 0.05 % after all levers) does not
  fire either. The outcome is outside both of the task's branches -> SURFACED TO THE MAIN LOOP (status blocked).
- Root cause: the per-sample load (A) alone is 5.4-9.0 ns/sample = 0.026-0.043 % of a core across the 20 runs,
  i.e. 79-131 % of the 0.033 % target before any solve. No R-1 lever acts on it except (2) (hoisting), which is
  negligible there. Split (diagnostic): envelope ~2.9 ns, DropPhaseLock correction + mirror ~1.9 ns, Quantized glide
  ~1.2 ns (one double division + floor per sample in the S4.2 counter law), declick ~0.07 ns.
- Machine note: the i9-13900HX is a laptop part; A is bimodal between ~5.6 and ~7.2 ns across runs taken 20 s apart
  (thermal/boost state), which alone moves F by ~0.008 %.
- What T011/T015 must implement in any case: lever (2) (hoisted Hermite coefficients) and lever (3) (per-node cache
  of 2^{(d+carry)/12} and b, one exp2(gamma b/12) per node per pass; it cuts the worst-case solve 40.1 -> 12.3 us).
  Lever (4) halves the forced evaluations (17 -> 9; B 12.3 -> 8.5 us) but its 4-pass cap is NOT proven here; T015
  must show the solve residual < 1e-9 cycles on every SC-013 cell before adopting it.

Decision needed from the main loop / user (one of):
  (a) accept F <= 0.05 % (the SC-019 bar itself) as the T005 gate with levers (2)+(3)[+(4)], giving up the
      0.033 % MSVC-headroom target that tasks.md set; the bar is unchanged;
  (b) keep the 0.033 % target and authorise per-sample reductions OUTSIDE R-1 (e.g. Quantized glide step
      boundaries as precomputed integer sample indices ceil(k N/|Delta|) instead of a per-sample division; S5.6
      mirror accumulating (f_h - f_res) once per 16-sample hold instead of per sample), then re-run T005;
  (c) re-measure on an isolated desktop-class machine (the laptop's boost-state bimodality alone spans 0.008 %).
