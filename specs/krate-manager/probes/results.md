# Plugin manager open questions: test results

Answers to the open-questions table in
`specs/krate-manager/reports/Krate Audio plugin manager design.md`. Tested 2026-10-29.

| Open question | Result | Evidence |
|---|---|---|
| Which Windows DAWs scan `%LOCALAPPDATA%\Programs\Common\VST3`? | **Not enough to make it the default.** REAPER, Bitwig, Studio One, Cakewalk and Cubase scan it. Ableton Live 12, FL Studio and Renoise do not, and FL Studio and Renoise cannot add a custom VST3 folder at all. | This machine: REAPER's `vstpath64` lists the folder and `reaper-vstplugins64.ini` holds the Krate plugins scanned from it; Bitwig 5.1.9's log scans it. Vendor docs: `research_notes/.../windows_per_user_vst3_daw_support.md`. |
| Does SmartScreen fire on an exe the manager downloads itself? | **No Mark-of-the-Web is written, so SmartScreen has nothing to check.** | `Vorago-1.0.1-Windows-x64.exe` downloaded with plain Node https: only the `:$DATA` stream, no `Zone.Identifier`. Authenticode `NotSigned`. Smart App Control is off on this box (`VerifiedAndReputablePolicyState=0`), so its hard block was not exercised. |
| Are `tauri signer` keys minisign-compatible? | **Yes, both ways. One key can sign manager updates and plugin archives.** | tauri-cli 2.12.4 key files are base64 of standard minisign files (`untrusted comment: minisign public key`, `rsign encrypted secret key`). A Tauri signature verified with `rsign verify`; an `rsign`-signed file verified against the Tauri public key; a one-byte tamper failed verification. |
| Does Tauri's bundler set `LSFileQuarantineEnabled`? | **No (source).** Files a Tauri app downloads with reqwest carry no quarantine unless the developer adds the key. | `tauri-bundler` `create_info_plist` writes no such key; zero hits in `tauri` and `plugins-workspace`. `research_notes/.../tauri_plist_quarantine_and_runners.md`. Runtime check: probe Q1, Q6-plist. |
| Does the Tauri updater add or strip quarantine on macOS? | **Neither (source).** It un-tars in memory into a temp dir on the same volume and swaps with `renamex_np`, falling back to an AppleScript admin prompt on permission errors. | `plugins/updater/src/updater.rs` `install_inner`, same note. |
| macOS: does a non-browser download carry quarantine? | **No, on Sequoia 15.7.9 and Tahoe 26.6.2.** Both Node https and curl downloads of the release pkg had no `com.apple.quarantine`. | Probe Q1, run 40900379475 on `macos-15` and `macos-26` (arm64). |
| Does `sudo installer -pkg` install a quarantined unsigned pkg, and is the payload quarantined? | **It installs (exit 0), and neither the .vst3 nor the .component is quarantined, on both versions.** `spctl` rejects the same pkg for a double-click install. | Probe Q2 and Q3-pkg. The manager can run the existing pkg through `installer` behind one admin prompt and get unquarantined plug-ins. |
| What signature does the shipped plug-in carry? | **Ad-hoc**, so it runs on Apple Silicon without a CI codesign step. `spctl` rejects it with or without quarantine, as it rejects anything without a Developer ID; that verdict says nothing about whether a host loads it. | Probe Q4, Q3-bundle (Vorago 1.0.1 release pkg). |
| Does an extracted archive keep quarantine? | **Yes.** `ditto -x` of a quarantined zip quarantines the extracted bundle; a clean zip extracts clean. A browser-downloaded plug-in zip would arrive quarantined, so manual downloads should stay pkg. | Probe Q5. |
| Tauri app as built: Info.plist key and ad-hoc signature | **No `LSFileQuarantineEnabled`; `codesign --verify --deep --strict` passes on the ad-hoc bundle**, on both versions. | Probe Q6-plist, Q6-sign (tauri-cli 2.12.4, `signingIdentity: "-"`). |
| Is a quarantined ad-hoc app blocked at launch on Tahoe? | **Yes, on Sequoia 15.7.9 and Tahoe 26.6.2. The unquarantined copy of the same build launches.** The quarantine flags stayed at `0083` after the attempt, so nothing approved it. Whether "Open Anyway" then appears in Privacy & Security is UI and could not be checked headless. | Probe Q6-launch, run 40901690699. Run 2 read "quarantined app ran" because it launched the clean copy first and macOS cached the approval, which is itself a finding: approval follows the code, not the path. |
| Does an ad-hoc Tauri app replace itself cleanly through the updater? | **Not tested.** It needs a real app with the updater plugin and an update feed. Source review shows the swap writes no quarantine. | `tauri_plist_quarantine_and_runners.md`. |
| Which `moduleinfo.json` Version should the manager trust? | **Either, after commit 294a26e7.** All nine bundles now carry the version.json version at top level and per class, gated by `tools/check-bundle.js`. | Release builds already published before the next release of each plugin still say 0.8.0 at top level; the manager must fall back to the class Version for those. |

## Consequence for the design

- **Windows keeps the system VST3 folder as the default**, behind one UAC prompt. Per-user cannot be the default while Ableton and FL Studio ignore it.
- **Windows installs and self-updates are prompt-free after the first launch**, because the manager's downloads carry no Mark-of-the-Web. The first download of the manager itself still gets SmartScreen's "Run anyway".
- **One minisign key** (generated with `tauri signer generate`) serves both feeds.
- **macOS: everything the manager downloads and writes is unquarantined**, on Sequoia and Tahoe. That holds whether it extracts a zip itself or runs the existing pkg through `sudo installer`. The pkg route gives system-wide installs and the pkgutil receipt, behind one admin prompt. The zip route into `~/Library/Audio/Plug-Ins` needs no prompt.
