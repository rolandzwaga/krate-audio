# Per-OS mechanics of detecting, installing, upgrading and uninstalling VST3 / AU plugins from a desktop manager (state as of 2026-10-29)

Scope note: "Steinberg requirement" / "Apple requirement" marks something the platform owner's documentation states; "practice" marks what DAWs or vendors do without a spec behind it. Where a fact was read from the Krate repository or an installed Krate bundle on this machine, the file path is given as the source.

## Key question 1 — Detection: standard search paths and reading a version without loading the plugin

### Takeaway
Steinberg specifies the VST3 folders per OS (user folder scanned first, then global, then application folder) and says VST3 needs no registration; a bundle carries `Contents/Resources/moduleinfo.json` with a top-level `Version` string and per-class `Version` strings, which is the only cross-platform, no-load version source. The single-file `.vst3` is deprecated since VST 3.6.10 but the SDK's own Windows host code still accepts a plain `.vst3` file; the Linux SDK host code does not.

### Cited Findings

VST3 search paths (Steinberg)
- Windows, in priority order: User `%LOCALAPPDATA%/Programs/Common/VST3/`; Global `/Program Files/Common Files/VST3/`; Global 32-bit-on-64 `/Program Files (x86)/Common Files/VST3/`; Application `$APPFOLDER/VST3/` — [Steinberg: Plug-in Locations](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical+Documentation/Locations+Format/Plugin+Locations.html)
- macOS, in priority order: User `/Users/$USERNAME/Library/Audio/Plug-ins/VST3/`; Global `/Library/Audio/Plug-ins/VST3/`; Global `/Network/Library/Audio/Plug-ins/VST3/`; Application `$APPFOLDER/Contents/VST3/` — [Steinberg: Plug-in Locations](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical+Documentation/Locations+Format/Plugin+Locations.html)
- Linux, in priority order: User `$HOME/.vst3/`; Global `/usr/lib64/vst3/` (noted as the Fedora definition); Global `/usr/lib/vst3/`; Global `/usr/local/lib64/vst3/`; Global `/usr/local/lib/vst3/`; Application `$APPFOLDER/vst3/` — [Steinberg: Plug-in Locations](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical+Documentation/Locations+Format/Plugin+Locations.html)
- The page says a plug-in "should be installed at specific folder location", that the host "should scan, at first, higher level of priority", that the "First found plug-in (for a given Processor UID) has to be used", that "VST 3 doesn't require a plug-in registration like it is used with DirectX", and that "Links, Symbolic links or Shortcuts could be used from these predefined folders" — [Steinberg: Plug-in Locations](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical+Documentation/Locations+Format/Plugin+Locations.html)
- The SDK's reference host code implements exactly these folders: Windows `Module::getModulePaths()` scans `FOLDERID_UserProgramFilesCommon\VST3`, then `FOLDERID_ProgramFilesCommon\VST3`, then `<exe dir>\VST3` — [vst3sdk module_win32.cpp, lines 557-609 (local copy F:\projects\iterum\extern\vst3sdk\public.sdk\source\vst\hosting\module_win32.cpp)](https://github.com/steinbergmedia/vst3_public_sdk/blob/master/source/vst/hosting/module_win32.cpp); Linux scans `$HOME/.vst3`, `/usr/lib/vst3/`, `/usr/local/lib/vst3/`, then `<app>/vst3` (the comment block lists only these three system-level paths, not the `lib64` variants from the web page) — [vst3sdk module_linux.cpp, lines 263-289 (local copy)](https://github.com/steinbergmedia/vst3_public_sdk/blob/master/source/vst/hosting/module_linux.cpp)

Bundle format (Steinberg)
- Windows bundle: `MyPlugin.vst3/Contents/x86_64-win/MyPlugin.vst3` (64-bit DLL), `x86-win`, `arm64-win`, `arm64ec-win`, `arm64x-win` ("Recommended architecture for Windows on Arm!"), `arm-win` (deprecated); optional `desktop.ini` + `Plugin.ico`. macOS: `MyPlugin.vst3/Contents/MacOS/` (Mach-O), `Contents/Info.plist`, optional `PkgInfo`. Other no-load version sources
- Windows: `GetFileVersionInfo` "Retrieves version information for the specified file"; call `GetFileVersionInfoSize` first and `VerQueryValue` to read the buffer; the fixed part (VS_FIXEDFILEINFO) holds the version number, the non-fixed part holds strings — [Microsoft Learn: GetFileVersionInfoW](https://learn.microsoft.com/en-us/windows/win32/api/winver/nf-winver-getfileversioninfow)
- macOS AU: Apple's TN2276 says AU properties are "now specified in the project's Info.plist" via an `AudioComponents` array of dictionaries with keys `description, factoryFunction, manufacturer, name, subtype, type, version` (example `version` integer `65536`), because "audio units no longer use the Component Manager on Mac OS X Lion or newer" — [Apple TN2276](https://developer.apple.com/library/archive/technotes/tn2276/_index.html)
- A JUCE thread reports auval's "Component's Bundle Version" is read from the embedded Info.plist and `CFBundleVersion` must match the version format to display correctly (community report, not Apple) — [JUCE forum](https://forum.juce.com/t/component-version-and-components-bundle-version/7859)
- The older Apple AU guide (pre-Lion) says the AU "identifies its version as an eight-digit hexadecimal number in its resource (.rsrc) file" and that the Component Manager "picks the most recent version if more than one is present on a system" — [Apple Audio Unit Programming Guide: Development Fundamentals](https://developer.apple.com/library/archive/documentation/MusicAudio/Conceptual/AudioUnitProgrammingGuide/AudioUnitDevelopmentFundamentals/AudioUnitDevelopmentFundamentals.html)
- Apple's current API exposes `AVAudioUnitComponent.version` as "the audio unit component version number" (a programmatic way to read installed AU versions from the registry rather than from files) — [Apple: AVAudioUnitComponent.version](https://developer.apple.com/documentation/avfaudio/avaudiounitcomponent/version.md)

AU folders (Apple)
- `~/Library/Audio/Plug-Ins/Components/` ("can be used only by the owner of the home folder") and `/Library/Audio/Plug-Ins/Components/` ("can be used by all users on the computer"); "It is up to you which of these locations you use or recommend to your users."; Apple's own units live in `/System/Library/Components/` — [Apple Audio Unit Programming Guide](https://developer.apple.com/library/archive/documentation/MusicAudio/Conceptual/AudioUnitProgrammingGuide/AudioUnitDevelopmentFundamentals/AudioUnitDevelopmentFundamentals.html)

### Inferences
- A manager can enumerate every Krate plugin on every OS by globbing the Steinberg folders for `*.vst3` directories and reading `Contents/Resources/moduleinfo.json`; the parser must accept JSON5 trailing commas (the Krate output has them). Which `Version` field to display needs a decision: the local Membrum bundle has top-level `Version` `0.8.0` but class `Version` `0.12.2.1`, so the two are not kept in sync by the Krate build.
- For the AU, `Contents/Info.plist` (`CFBundleShortVersionString` plus `AudioComponents[0].version`) is readable with a plist parser without loading; the user-level vs system-level choice is explicitly left open by Apple.
- A single-file Windows `.vst3` can be detected by `is_regular_file` on a `.vst3` path; on Linux the SDK path requires a directory, so single-file detection is only a legacy-Windows concern.

### Gaps
- The exact Steinberg portal page documenting the moduleinfo.json schema and the 3.7.8 "breaking change" was not retrieved (404 on the guessed URL); the schema above is from the SDK header and an SDK 3.8.0 output file.
- No Apple document retrieved states that `CFBundleShortVersionString` is the authoritative AU version; TN2276 gives the `AudioComponents.version` integer and the JUCE report concerns `CFBundleVersion`.

## Key question 2 — Strategy A facts: driving the existing installers

### Takeaway
Inno Setup gives a complete silent lifecycle: `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /LOG="file"` on install, exit codes 0-8, an uninstall key `…\Uninstall\{AppId}_is1` in the 64-bit HKLM view for Krate's admin-mode 64-bit installers, and an uninstaller that may return its exit code before the work is done. macOS `installer -pkg X -target /` needs root, logs to `/var/log/install.log`, leaves a `pkgutil` receipt with `version`, and there is no native uninstall. Linux has no installer at all today.

### Cited Findings

Inno Setup — Setup command line
- `/SILENT`, `/VERYSILENT`: "Instructs Setup to be silent or very silent."; silent shows only the progress window, very silent shows nothing; "If it's very silent it will reboot without asking." unless `/NORESTART` — [Inno Setup Help: Setup Command Line Parameters](https://jrsoftware.org/ishelp/topic_setupcmdline.htm)
- `/SUPPRESSMSGBOXES`: "Instructs Setup to suppress message boxes. Only has an effect when combined with /SILENT or /VERYSILENT." — [same](https://jrsoftware.org/ishelp/topic_setupcmdline.htm)
- `/NORESTART`: "Prevents Setup from restarting the system following a successful installation, or after a Preparing to Install failure that requests a restart." — [same](https://jrsoftware.org/ishelp/topic_setupcmdline.htm)
- `/LOG`: log in the user's TEMP directory "with a unique name based on the current date"; `/LOG="filename"`: fixed path, "If a file with the specified name already exists it will be overwritten." — [same](https://jrsoftware.org/ishelp/topic_setupcmdline.htm)
- `/CLOSEAPPLICATIONS`: "Instructs Setup to close applications using files that need to be updated by Setup if possible."; `/FORCECLOSEAPPLICATIONS`, `/RESTARTAPPLICATIONS` exist; `/DIR="x:\dirname"` overrides the destination (fully qualified) — [same](https://jrsoftware.org/ishelp/topic_setupcmdline.htm)
- `/CURRENTUSER` / `/ALLUSERS` select non-administrative / administrative install mode and "Only has an effect when the [Setup] section directive PrivilegesRequiredOverridesAllowed allows the commandline override." — [same](https://jrsoftware.org/ishelp/topic_setupcmdline.htm); `PrivilegesRequiredOverridesAllowed` default is blank (no override allowed); values `commandline`, `dialog` — [Inno Setup Help: PrivilegesRequiredOverridesAllowed](https://jrsoftware.org/ishelp/topic_setup_privilegesrequiredoverridesallowed.htm)
- `/RESTARTEXITCODE=n` sets a custom exit code when a restart is needed after success ("By default, 0 is returned in this case.") — [same](https://jrsoftware.org/ishelp/topic_setupcmdline.htm)

Inno Setup — exit codes
- Setup: 0 success (or /HELP); 1 "Setup failed to initialize."; 2 user cancelled before installation started; 3 fatal error preparing to move to the next phase; 4 "A fatal error occurred during the actual installation process."; 5 user cancelled during installation; 6 terminated by debugger; 7 Preparing to Install determined Setup cannot proceed; 8 same but a restart is needed — [Inno Setup Help: Setup Exit Codes](https://jrsoftware.org/ishelp/topic_setupexitcodes.htm)
- Uninstaller: "The uninstaller will return a non-zero exit code if the user cancels or a fatal error is encountered."; "any non-zero exit code indicates that the uninstaller was not run to completion" and callers should not test for a particular value; the uninstaller copies itself to TEMP and the original process exits first ("at which point you get an exit code back") while the clone deletes the original EXE — i.e. the exit code can arrive before removal is complete — [Inno Setup Help: Uninstaller Exit Codes](https://jrsoftware.org/ishelp/topic_uninstexitcodes.htm)

Inno Setup — uninstaller command line
- `/SILENT`: no startup confirmation, no "uninstall complete" message, shared files removed without prompting, critical errors still shown; `/VERYSILENT`: also hides the progress window and will reboot without asking if a reboot is needed and `/NORESTART` is absent; `/SUPPRESSMSGBOXES` only with /SILENT or /VERYSILENT; `/LOG` writes to TEMP with a unique name ("It will not overwrite or append to existing files."); `/NORESTART`: "Instructs the uninstaller not to reboot even if it's necessary." — [Inno Setup Help: Uninstaller Command Line Parameters](https://jrsoftware.org/ishelp/topic_uninstcmdline.htm)

Inno Setup — registry / AppId / mode
- The uninstall registry key name is AppId with `_is1` appended (AppId `MyProgram` → `MyProgram_is1`); AppId is also stored in `unins???.dat` and a later install appends to an existing uninstall log only if AppIds match; limit 127 characters after constant expansion — [Inno Setup Help: AppId](https://jrsoftware.org/ishelp/topic_setup_appid.htm)
- Administrative install mode: "auto" constants map to the "common" forms and "HKA, uninstall info, and font install root keys map to HKEY_LOCAL_MACHINE"; non-administrative mode: map to the "user" forms and HKEY_CURRENT_USER — [Inno Setup Help: Installation Modes](https://jrsoftware.org/ishelp/topic_admininstallmode.htm)
- In 64-bit install mode "The Uninstall key is created in the 64-bit view of the registry." and "The {commoncf} constant is equivalent to {commoncf64}." — [Inno Setup Help: 32-bit vs 64-bit Installation](https://jrsoftware.org/ishelp/topic_32vs64bitinstalls.htm)
- `PrivilegesRequired=admin` (the default) always runs with administrative privileges in administrative install mode and Windows asks an unprivileged user for an administrator password; `lowest` never requests elevation ("Do not use this setting unless you are sure your installation will run successfully on unprivileged accounts.") — [Inno Setup Help: PrivilegesRequired](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm)

### Inferences
- Strategy A on Windows: run `<Setup>.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /LOG="<path>"`, wait on the process, treat exit 0 as success and 1-8 per the table; the UAC prompt comes from Inno (`PrivilegesRequired=admin`) so the manager itself need not elevate. Uninstall: read `QuietUninstallString`/`UninstallString` from `HKLM\...\Uninstall\{GUID}_is1` (64-bit view) and run it with `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`; because the uninstaller's exit code can precede completion, poll for the `.vst3` folder's disappearance before declaring success.
- Strategy A on macOS: the manager must obtain root for `installer -pkg`; the receipt `com.krateaudio.<plugin>` then provides `version` and `--files` for detection and for a manager-implemented uninstall (`rm` the listed paths, then `pkgutil --forget`). An unsigned pkg run through the CLI never passes through LaunchServices, which is the only documented Gatekeeper trigger, so the pkg content itself is not what gets blocked; the manager app's own notarization status is what Gatekeeper evaluates.
- Strategy A on Linux is impossible as shipped; the manager must do Strategy B there regardless.

### Gaps
- No Apple document or DTS statement was found that explicitly says `/usr/sbin/installer` skips Gatekeeper for unsigned pkgs; the evidence is the LaunchServices mechanism plus admin practice. A test on a quarantined copy of a Krate pkg would settle it.
- Inno's help does not list `QuietUninstallString` on the pages fetched; its presence in Inno-written keys is well known but was not confirmed from the Inno docs in this pass (verify in a registry dump of an installed Krate plugin).
- Inno's behaviour for in-use files under `/VERYSILENT` (the "file in use" / restart-replace path) was not found on the pages fetched.

## Key question 3 — Strategy B facts: what the manager must do itself per OS

### Takeaway
Writing to the Steinberg user folders (`%LOCALAPPDATA%\Programs\Common\VST3`, `~/Library/Audio/Plug-Ins/{VST3,Components}`, `~/.vst3`) needs no elevation on any OS, and Apple explicitly allows the user-level Components folder; system folders need UAC (`runas` → `ERROR_CANCELLED` on refusal), root (no supported one-shot API — AEWP is deprecated, osascript is "equivalent to sudo"), or `pkexec`. A loaded Windows DLL can be renamed-then-replaced without a reboot; nothing comparable blocks replacement on macOS/Linux.

### Cited Findings

Elevation — Windows
- `ShellExecuteEx` returns `ERROR_CANCELLED` when "The function prompted the user for additional information, but the user canceled the request." (the UAC-refused case); `ERROR_ACCESS_DENIED` is also enumerated; COM should be initialised first — [Microsoft Learn: ShellExecuteExW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecuteexw)
- Inno's PrivilegesRequired page confirms the OS behaviour the manager would reproduce: for an unprivileged user "Windows asks for the password of an account with administrative rights" — [Inno Setup Help: PrivilegesRequired](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm)
- The SDK host scans `FOLDERID_UserProgramFilesCommon\VST3` (i.e. `%LOCALAPPDATA%\Programs\Common\VST3`) first; this folder is per-user and needs no elevation — [module_win32.cpp lines 561-576](https://github.com/steinbergmedia/vst3_public_sdk/blob/master/source/vst/hosting/module_win32.cpp)

Elevation — macOS
- Apple DTS (Quinn): "I don't consider the AppleScript approach (`do shell script … with administrator privileges`) to be a valid alternative to the long-deprecated `AuthorizationExecuteWithPrivileges` (AEWP)."; "The problem with AEWP is that there's no secure link between the code asking to elevate privileges and the code that's run with elevated privileges. `SMJobBless` fixes that."; "`SMJobBless` (a non-deprecated API, but a ton of work)"; "I view the AppleScript facility as equivalent to `sudo`: It's intended to be used by system administrators, and not as API."; "If you already have an installer package in play, there's no need for `SMJobBless`." — [Apple Developer Forums thread 701118](https://developer.apple.com/forums/thread/701118)

### Inferences
- Strategy B without elevation is feasible on all three OSes by targeting the Steinberg/Apple user folders. The trade-offs are (a) coexistence with existing admin installs in the global folders (Steinberg's "first found wins" rule means a stale global copy would shadow a user-folder update unless the manager removes it, which needs elevation once), and (b) the DAW-support question for `%LOCALAPPDATA%\Programs\Common\VST3` (see KQ5).
- On Windows the rename-then-copy sequence lets the manager update a plugin while a DAW holds it; the delayed-delete step needs admin, so a non-elevated manager should instead leave the renamed file and clean it up on a later run.
- On macOS the supported ways to obtain root are an installer package (Strategy A) or an SMAppService/SMJobBless helper; `osascript … with administrator privileges` works but Apple classifies it as a sudo-equivalent, not API.
- Presets in `ProgramData` / `/Library/Application Support` also need elevation; a Strategy B manager that avoids elevation must move presets to a per-user path or accept that factory presets remain an elevated step.

### Gaps
- No Apple documentation was retrievable (JavaScript-only pages) for SMAppService's introduction version or AEWP's exact deprecation text; the forum quotes above are the best primary-adjacent evidence.
- No source was found on whether a non-elevated process can rename a loaded DLL inside `C:\Program Files\Common Files\VST3` (ACLs make that admin-only in practice, but no Microsoft page was fetched that says so).

## Key question 4 — macOS Audio Unit registration, cache refresh, and quarantine

### Takeaway
Apple's documented refresh is: restart, Logic's Plug-in Manager "Reset & Rescan Selection" / "Full Audio Unit Reset", and as a last resort removing `~/Library/Caches/AudioUnitCache`; `killall -9 AudioComponentRegistrar` is community practice (process exists from 10.13 on) that works in postinstall scripts for some and not for others. Quarantine is attached only by apps that opt in via `LSFileQuarantineEnabled` (or CoreTypes exceptions) — `curl` does not — and the blocked-plug-in reports all trace back to quarantined, unsigned bundles fixed with `xattr -rd com.apple.quarantine`.

### Cited Findings

Registration / cache
- Apple's AU guide (Component Manager era): the registry is refreshed "on system boot, on user log-in, and whenever the modification timestamp of one of the three Components folders changes"; "Only registered audio units are available to host applications." — [Apple AU Programming Guide](https://developer.apple.com/library/archive/documentation/MusicAudio/Conceptual/AudioUnitProgrammingGuide/AudioUnitDevelopmentFundamentals/AudioUnitDevelopmentFundamentals.html)
- Apple Support (Logic Pro / MainStage): steps are restart the Mac; Settings > Plug-in Manager to confirm installation; "Reset & Rescan Selection" for a plug-in marked "failed validation"; "Full Audio Unit Reset" then close and reopen Logic; last resort: Finder > Go > Library (Option key) > Caches > AudioUnitCache, move its files out, restart, reopen — the scan "can be lengthy" and AU apps are unavailable meanwhile; "32-bit plug-ins aren't compatible with Logic Pro or MainStage." — [Apple Support 122179](https://support.apple.com/en-us/122179)
- `auval -a` "lists all available AudioUnits of any type"; `-v TYPE SUBT MANU` validates one unit; `-s TYPE` lists by type — [auval(1) man page mirror](https://www.unix.com/man_page/osx/1/auval/)
- Community practice: `killall -9 AudioComponentRegistrar` posted by olilarkin (2020-03-20); pflugshaupt: "Confirmed working with a post-install script on my AU installer package."; RolandMR: `killall` returns an error when no process matches, so end postinstall scripts with `exit 0`; ttg: "10.12 or below has no AudioComponentRegistrar process."; yfede (2020-09-02, macOS 10.15.6): killall did not fix an auval "didn't find the component" error but a reboot did; matkatmusic (2021): moving the plugin out of Components, waiting ~10 s and moving it back works without restart; pflugshaupt (2018) found the mv workaround worked for `~/Library/Audio/Plug-Ins` but a pkg to the system-wide Library "did not respond to any of the workarounds, and only a restart worked" — [JUCE forum thread 26753 page 1](https://forum.juce.com/t/installing-new-audio-units-requires-restart-in-high-sierra/26753) and [page 3](https://forum.juce.com/t/installing-new-audio-units-requires-restart-in-high-sierra/26753?page=3)
- Eventide support suggests `killall -9 cfprefsd` then `killall -9 AudioComponentRegistrar`, then restart Logic — [Eventide support thread](https://www.eventideaudio.com/?p=116359); a 2024 report says killing the registrar "doesn't do the trick anymore these days" and deletes `~/Library/Caches/AudioUnitCache/` instead — [JUCE forum: Plugin manager](https://forum.juce.com/t/plugin-manager/66963)
- A JUCE thread (macOS 15 Sequoia) reports an AU not appearing in GarageBand even after `pluginkit -a` and `AllowUnsignedAudioUnits`, with no confirmed resolution — [JUCE forum 68573](https://forum.juce.com/t/au-plugin-not-showing-up-in-garageband-on-macos-15-sequoia-is-there-a-free-workaround/68573)

Quarantine
- Apple Platform Security: Gatekeeper "verifies that the software is from an identified developer, is notarized by Apple to be free of known malicious content, and hasn't been altered", "requests user approval before opening downloaded software for the first time", "tracks the provenance of files written by downloaded software", and "protects against the distribution of malicious plug-ins with benign apps"; "users can override Gatekeeper policies to open any software unless restricted by a device management service" — [Apple: Gatekeeper and runtime protection in macOS](https://support.apple.com/guide/security/gatekeeper-and-runtime-protection-sec5599b66df/web)
- Who attaches the xattr: when an app's Info.plist sets `LSFileQuarantineEnabled` to true, "all files created by that app should bear the xattr"; apps without the key fall back to CoreTypes `Exceptions.plist` overrides (e.g. Transmission is forced on); `curl` is exempt — "It's simple to demonstrate that the download then doesn't have any quarantine xattr attached to it" — and curl downloads "don't gain the xattr when extracted from archives either" — [Eclectic Light: Who decides to quarantine files? (2025-12-08)](https://eclecticlight.co/2025/12/08/who-decides-to-quarantine-files/)
- Palo Alto Unit 42: Apple explains that Unix networking tools such as scp and curl won't mark downloads as quarantined; malware families use curl to bypass Gatekeeper this way — [Unit 42: Gatekeeper bypass](https://unit42.paloaltonetworks.com/gatekeeper-bypass-macos])
- Plug-in reports: Ecamm says newly installed audio components "may not work because they are quarantined by Apple's Gatekeeper security" — [Ecamm support](https://support.ecamm.com/en/articles/8577652-using-quarantined-audio-components); HISE forum: macOS adds the attribute to downloaded files lacking a valid signature and the fix is `sudo xattr -rd com.apple.quarantine /Library/Audio/Plug-Ins/Components/*` (and VST3 equivalents) — [HISE forum 96762](https://forum.hise.audio/post/96762); JUCE forum: "'Open Anyway' doesn't work on VST3 plugins" for unsigned builds — [JUCE forum 64574](https://forum.juce.com/t/mac-open-anyway-not-working-for-unsigned-mac-vst3/64574); KVR thread on installing unsigned VST3 on Ventura — [KVR](https://www.kvraudio.com/forum/viewtopic.php?p=8945829)
- Apple DTS (Mach-O signing thread): when a quarantined command-line tool is double-clicked in Finder, Terminal runs a document Gatekeeper check that "always fails no matter how well signed or notarised the tool is" — [Apple forums 689337](https://developer.apple.com/forums/thread/689337)
- Krate's CI builds the macOS plugins with `SMTG_DISABLE_CODE_SIGNING=ON` (a workaround for Xcode 16+ `-adhoc_codesign`), and the release workflow has no codesign/notarize step — [F:\projects\iterum\.github\workflows\ci.yml line 600](file:///F:/projects/iterum/.github/workflows/ci.yml); [release.yml](file:///F:/projects/iterum/.github/workflows/release.yml)

### Inferences
- A manager that downloads with its own HTTP client (not a browser) and has no `LSFileQuarantineEnabled` key in its Info.plist will write `.vst3`/`.component` bundles without `com.apple.quarantine`, which removes the documented trigger for the "quarantined unsigned plug-in" failures above. Apple's "tracks the provenance of files written by downloaded software" sentence means the manager's own download provenance is recorded, but the sources found show no case where that alone blocked a plug-in load.
- A manager written with a framework that opts into quarantine (or a user who extracts a zip via Archive Utility from a browser download) produces quarantined bundles; the manager should either strip the xattr itself (`xattr -dr com.apple.quarantine <bundle>`, user-owned paths need no root) or verify its absence after install.
- For AU pickup the manager should: install, then run `killall -9 AudioComponentRegistrar` ignoring its exit code, then offer the Logic "Full Audio Unit Reset" instructions, and tell the user a restart is the only guaranteed path for system-level installs (per the 2018 report and Apple's own step 1).

### Gaps
- No Apple document describes `AudioComponentRegistrar` or sanctions killing it; everything about it is community practice.
- No source was found confirming whether macOS 15/26 refuses to load a quarantined but ad-hoc-signed or unsigned AU outright (the Sequoia GarageBand thread is unresolved).
- Whether files written by an app that is itself quarantined inherit the flag was not addressed by any source found (the Big Sur article found installed files were *not* quarantined after a quarantined pkg ran via Installer).
