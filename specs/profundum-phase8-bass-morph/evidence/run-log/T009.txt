Decisions
  1. SC-009(a): the three "no audio member" checks are variable templates over a requires-expression
     (bmcHasStereoBlock / bmcHasScalarProcess / bmcHasMonoBlock). A requires-expression on a NON-dependent operand
     is ill-formed (a hard error on GCC / Clang) instead of false, so the literal
     static_assert(!requires(BassMorphEngine& e, ...) { ... }) of tasks.md would not compile portably. Each
     detector has a positive control on a real audio member (ProfundumCore::processBlock(L, R, n),
     DCBlocker::process(float), DropEnvelope::processBlock(x, n)), so a detector that always reads false is caught.
  2. SC-009(b): convergence = shapeGains() bitwise unchanged for 8 consecutive 32-sample intervals, cap 4 000
     (REQUIRE). Also CHECKs that shapeOf(resolved recipe) differs from each endpoint's (the p is truly interior).
     Positive control: crossfade and p = 0.5 read on the core-tap mid over the descriptor read window (settle 1 s,
     one kLowFrequencyFftSize frame), harmonics 1-16, max |dB difference| >= 1.
  3. SC-010: showcasePair(), 0 -> 1 Position event at sample 4800, default ramp and amp envelope (the fixture
     default; the criterion reads only the call grid and the per-voice Resolved). Also CHECKs advanceSamples
     strictly increasing and that p went 0 -> 1 (the voices are compared across a moving state).
  4. SC-015: "moves by >= bar" read as signed travel D(1) - D(0) (SC-008(b)'s net-travel definition); D_t as the
     ratio D_t(1) / D_t(0). D_st reads f_c from each render's resolved field.crossoverHz. Every clause is a CHECK so
     the CSV and all rows are produced on a red.
  5. SC-023: the harness applies the four resolved Drop leaves at every grid point (before the trigger at sample 0
     and at 2.5 s). Teeth: CHECK that the setters were fed values different from A's while the first Drop was
     active, and that A's and B's trajectories differ. The 2.5 s grid point REQUIREs p == 1 and the four resolved
     leaves == B's bitwise before the second trigger.
  6. FR-039 harness: `step` at a grid sample = output of the envelope with that interval's setters minus a copy
     taken BEFORE them (the twin), processing the same sample; the expected value uses a test-side replication of
     the decay table phase (adsr_envelope.h:313 increment; :471-474 enterDecay latches phase 0 and the increment)
     and the same generatePowerCurveTable / lookupCurveTable (core/curve_table.h:65, :177) the envelope uses.
     logStartLevel = peak = 1 (attack ends at peakLevel_, then enterDecay). Range in (iii) = 1 - sustain (0.5).
  7. FR-039 cases run in sequence in one TEST_CASE body (not SECTIONs), so amp-envelope-immediate.txt collects
     the (i)-(iii) rows in one run (with SECTIONs every re-entry would overwrite the file with one row).
  8. SC-024: maxDeltaAround centre = g_sw + len/2, half-width = ceil(len/2), len = window end - g_sw, so the read
     covers W = [g_sw, g_sw + transitionEndSamples(CharacterAlgorithm) + ceil(fs/f0)] on transition and reference
     alike. Differential clicks over [g_sw - 2400, window end] inclusive, refStart = A static (A = B = base),
     refEnd = A' static (A = B = A'), both at p 0.3. Also CHECKs the resolved algorithm == Fold at the g_sw interval.
  9. SC-005 rendered: level(p) = the render's resolved anchor.level (last interval); the handed (Mass-biased)
     level is recorded beside it (Mass 50 -> equal). w1 = Bmt::readWindowHarmonicPowers of the Anchor-tap mid,
     relative to the p = 0 Lock render. (e) is signed: D_nl(Mass 100) - D_nl(Mass 0) >= 3 dB in Lock.
 10. SC-006(b): constrained pairs = randomValidPair(seed 0x8066) then, per side, motionDepth 0, anchor.mode
     Lock / Follow from one raw mt19937 word (bit 0), dropAmountSt 0. The "A alone" reference is rendered once per
     pair with A = B = A (at p = 0 the resolved state is A bitwise in every mode, SC-001), reused for the three
     modes (optimisation: 32 renders instead of 48). t_land = advanceSamples of the first interval at or after the
     0.75 s event whose resolved position is +0; CHECKs p reached 1 first. Harmonics compared: those within 60 dB of
     the strongest on EITHER render (the stricter union).

Deviation
  D1. FR-039 case (iv) (decayMs 50 -> 2000) morphs at 32 ms instead of the harness's 200 ms. A's 50 ms decay runs
      from ~10 ms to ~60 ms (attack 10 ms default), so a 200 ms morph lands after the Sustain entry and the
      "bitwise equal until the Sustain entry" clause would assert nothing. At 32 ms the 5 ms ramp (8 intervals)
      lies inside Decay; the case REQUIREs that the decayMs setter fired more than once and at least once while
      the stage was Decay. No bar changed.
