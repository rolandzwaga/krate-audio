## Implementation Notes — Deviations Reported by Task Agents

1. **FR-011 kind-assignment defect, found and fixed (T006 → later tasks).** T006's fail-first test discovered that the original with-replacement remainder draw in `initialiseState()` could put two remainder units on the same kind, violating FR-011's "max-min ≤ 1" requirement (measured: 14 of 48 grid cells violated it, e.g. `[0,0,0,4,0]` at agentCount=4). The fix — a seeded partial Fisher-Yates draw of `rem` *distinct* kinds — is what ships; FR-011's compliance verdict above reflects the corrected code, confirmed passing.
2. **FR-071 perturbAgent correction (S14 D-L).** The negative (giving) branch was corrected to `max(a * max(0.0, energy_[i] - preyFloorAbs_), -energy_[i])` — an inner `std::max(0.0, …)` not present in the original spec wording, needed to prevent an agent inside its own refuge floor from driving the pool negative. T011/T012 flagged that spec.md's FR-071 text still carried the uncorrected form as a documentation gap; this was closed in the same amendment pass that resolved FR-083 (spec.md now matches the code).
3. **FR-083 guard-ladder repair math amended in spec.md.** Two deviation clauses (pool computed as `energyBudget − bodies` rather than a difference of possibly-NaN quantities; repaired agents charged pro-rata against the mean-share target rather than treated as an entitlement) were added to spec.md FR-083 to match the implementation, in the same form as the FR-071 D-L correction.
4. **`wrap01` half-open contract fix (T010).** The plan's pseudocode `t - floor(t)` can round to exactly `1.0` for a sub-ULP negative input; the shipped form adds a `>= 1.0 → 0.0` snap so the stated `[0,1)` contract is actually true (probability of hitting this ~1e-6 per call).
5. **`hasShortCycle` zero-variance guard defect, found and fixed (T017).** The metrics-helper falsification caught a real bug: comparing `sumSquaredDeviations == 0.0` failed for a constant series whose float-summed deviation is `1.68e-25`, not bit-exact zero — causing the guarded "constant series is a cycle" escape to never fire. Fixed to compare every sample against `series.front()` directly (exact for any representable value).
6. **FR-085/FR-082 CPU-budget escalation, resolved by two user rulings (2026-09-16), not by relaxing the ceiling.** Initial worst-case measurements missed the 53,333 ns budget at `stepIntervalChunks=1` (~404,614 ns) and even after optimisation (L1-L3, E-1-E-3 levers) missed at floor=4 (60,176 ns). The user narrowed `kMinStepIntervalChunks` from 1→4→8 (spec.md FR-082) rather than raising the ceiling; final measured worst case at the floor of 8 is 29,074.0–50,280.8 ns/block depending on run, both under budget. The optional LUT-approximation lever (L4/L5) was explicitly declined by the user and correctly does not appear in the shipped header.
7. **SC-002/SC-005 gate moved from per-agent to population-mean output by user ruling (2026-09-16).** The per-agent form of the "no short limit cycle" and late-window-liveness clauses measured failures (3/32 agents, 127/500 sane-box deaths, 52.8% sane-box liveness vs the 70% gate) that the user judged not to reflect the intended criterion; the gate was moved to the population-mean output series, which is what ships and passes (SC-013 measures 78.2% alive).
8. **T015 (perf-test authoring) reported `blocked`, not `done`**, because its instructions forbade building/running and its own task explicitly requires a measured table before T016's lever-list decision could be taken. The measurement was completed in a later pass (T016, cpu-t016c log) and both arms pass; T015's file (`ecosystem_engine_perf_test.cpp`) itself was fully authored and not re-implemented.
9. **T023 (full five-suite + `[long]`-lane run) reported `blocked`** for the same reason — build/run was out of scope for that individual task, and existing logs on disk at the time were stale relative to the longrun TU's last edit. The build/run was subsequently completed (evidenced by the "RAN" citations throughout the SC/CC table above, including the full `dsp_systems_tests`: "All tests passed (6343628 assertions in 1375 test cases)").
10. **FR-090 evidence notes three transient red results** in an unrelated concurrent suite run (`harmonizer_engine_test.cpp` CPU benchmark, two `spectral_morph_render_test` bad-allocation failures) that were re-run alone and passed — attributed to resource contention from a concurrent sibling run, not a regression, and not part of Phase 8's own code.
11. **CC-warnings clang-tidy header-filter gap, found and fixed (T024).** The repo's `.clang-tidy` `HeaderFilterRegex` uses forward slashes, which does not match the backslashed absolute paths MSVC's `compile_commands.json` produces on Windows — meaning a tree-wide clean run was silently excluding `ecosystem_engine.h` from analysis.
