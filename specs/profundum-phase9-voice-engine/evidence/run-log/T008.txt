DECISIONS
- Event model (C-9): note-ons and note-offs share the 256-entry queue in arrival order (so an off-then-on re-press and
  an on-then-off short note inside one interval both resolve correctly); a full queue drops a note-on (counted by
  droppedEvents()) and diverts a note-off into the 128 pending-release flags, drained after the queue. Velocity 0 is a
  note-off. Pitch bend, tempo and every FR-031 setter are pending values applied at FR-026 step 1 (change-only); the
  morph surface and the macros are forwarded directly, because BassMorphEngine and the matrix are read only at the
  grid step (the latch is the component's own).
- Grid step exactly in FR-026 / S6.5 order. Motion restart (FR-045): voices are polled with consumeEnvelopeRestart()
  between motion_.setConfig and motion_.advanceInterval, so a restart applied at step 1 is heard this interval; one
  applied at a dip's switch sample inside render is picked up at the next grid point (<= 32 samples).
- f_res per voice: a followsMono flag per voice (set by a MONO note event, cleared by a POLY one) selects the MONO
  portamento trajectory or fNote * ratio, so a voice releasing across a MONO <-> POLY switch keeps its pitch
  (mono_.reset() keeps the glide pitch, mono_handler.h:392-403).
- The MONO voice gets fNote = 0 (plan S6.7 "fNote unused in MONO").
- Detector key (step 8): the lowest of the audible voices' currentCoreF0(), or that voice's f_res[0] when it has not
  rendered yet; 0 when none is audible.
- C-2 / S6.10: DcResync is logged only when the copy runs (one record per SOLID entry, as S6.10 writes it); every
  other engine step logs once per interval with an `issued` flag. Engine records carry voice = kEngineRecordVoice
  (0xFF).
- Sum buffers are cleared to -0.0f (the IEEE additive identity), so with one voice the Sum tap is that voice's
  contribution bit for bit (SC-019(b), T010).
- prepare / reset hand every MassDynamics setter directly; the first grid point after them hands everything again
  (C-20), change-only after that.

DEVIATIONS (surfaced)
1. PostSum (C-14) is built on an engine-internal ProfundumEngineObserver adapter that reads each voice's core /
   Anchor / feed / gAmp / gD / fCore taps into buses (core and feed multiplied by g_amp * g_d, the Anchor bus added
   after the global Character stage), then runs one global ShapeMorph -> + feed -> HarmonicFold -> BassCharacterStage
   at the per-sample lowest f_core. ProfundumVoice (T007, outside this task's file list) has no render path that
   stops after the core and the Anchor, so in PostSum the per-voice Shape / Fold / Character still execute and their
   output is discarded, and FOLLOW reads the voice's own perceivedPitchRatio, not the global stage's. The SOUND is
   C-14's; the CPU SAVING that SC-004 (T020) measures is NOT realised. Before T020's PostSum number is trusted, an
   append to profundum_voice.h (a core-and-Anchor-only render plus an external FOLLOW ratio) is needed: a decision
   for the main loop. The global Rectify flag stays false (no global meter) and no global syncPhase is issued.
2. Includes: plan S2's list plus processors/note_memory.h, systems/shape_morph.h, processors/harmonic_fold.h,
   processors/spectral_shape_recipe.h, systems/morph_state.h, systems/profundum_core.h,
   systems/bass_character_stage.h (used directly by the engine; S2's own rule "every symbol a header uses is
   included directly" outranks the list's omission).
3. Getter names (FR-066): getEndpoint(e) and morphPosition() as the task names them; the others are the setter's noun
   (voiceMode(), polyphony(), monoPriority(), legato(), portamentoTimeMs(), portamentoMode(), glideMode(),
   noteMemoryMode(), noteRetrigger(), pitchBendRange(), outputCeilingDb(), macros(), macro(m), seed(), pitchBend(),
   tempoBpm(), morphRampMs(), anchorMorphMode()). Added diagnostics: voiceSeed(v) (C-19's stored per-voice seeds),
   kEngineRecordVoice, kNumMidiNotes, kMaxBendRangeSt, kMin/kMaxSampleRate.
4. VoiceEngine_EventsLatchedToGrid compares a note issued at sample 69 with one issued at sample 96 (the grid point
   both latch to) under the identical host partition [64][5][27][32][64 ...], so the case isolates the latch from
   partition invariance (SC-012, T011). Positive control: the note issued at sample 64 (a grid point) differs.
   The queue arm runs MONO and POLY: 300 note-ons in one interval -> droppedEvents() == 44; the note-offs are issued
   0.25 s later and the last 100 ms of a 3 s tail must peak <= 1e-6.

RISKS / FINDINGS FOR LATER GROUPS
- ProfundumVoice::release() during a pending declick dip: the deferred transition applied at the switch sample calls
  ampEnv_.gate(true) when envelopeRestart is set, re-gating a released voice (profundum_voice.h applyTransition /
  applySwitch). A note-off landing inside the 1.5 ms dip can therefore leave the voice held until its next note-off
  (the Phase 4 harness has the same order). T008's queue arm issues its note-offs 0.25 s after the note-ons, so it does
  not exercise this; T015 (click grid) / T019 (soak) should, and the fix belongs to the voice (T007's file).
- MONO classification mirrors the harness: under LowNote / HighNote priority a non-winning key press is still
  classified Overlap and resolved by Note Memory (the harness never exercised non-LastNote priority).
