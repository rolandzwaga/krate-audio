DECISIONS
1. Bases. Rows on A use A_s (C-8), named "A + sustain 1 (C-8)". AT-48 (Dark <-> Bright) is gated on B_s
   ("B + sustain 1 (B10-1)"), and its A_s reading is a second, ungated line. AT-26's second cell, AT-27 and AT-28 use
   B as the spec names it (C-8: "B keeps its own 0.8"). The morph rows use the pair (A_s, B).
2. Readers. These are the Phase 8 readers on the engine taps (asFieldTaps). D_nl is always the Character tap over the
   forceLinearCore twin's core tap. D_t runs on the Phase 8 gate render on the Sum tap. A local copy (auDtMs) drops
   the reader's REQUIRE, so a render that never falls 80 dB is recorded as invalid instead of aborting the shard.
   The output-tap reading is written beside every row: the same descriptor on the output where one exists,
   otherwise L_K of the output.
3. value. Non-macro rows use |hi - lo|, or max / min for time ratios ("moves its descriptor by"). Macro rows use
   the documented axis direction (hi - lo, hi / lo), as the T014 harvest did. D_st cells also require Phase 7's band
   validity (G8-1, -60 dBFS) for both readings, because a band with no content above 2 f_c is not a width reading
   (Phase 8 B10-4).
4. AT-24 per-row setting, written into the spec table. This is FR-080's "Showcase inert" rule, applied on an
   analytic bound. On any sustain-1 base the 1 s hold of the gate render dominates D_t:
   D_t(0.1 ms) >= ~1015 ms and D_t(500 ms) >= 515 ms, so the ratio is <= 1.97 < 2 on A_s and B_s alike, and on B's
   own sustain 0.8 in the same way. The row therefore uses plain A (decay 150 ms, sustain 0). The A_s reading is
   recorded ungated beside it.
5. AT-25 "release reading": D_t of the gate render from the note-off grid point on, normalised by that segment's
   own peak period.
6. AT-11 / AT-12: E_sub over [note-on, note-on + punchTimeMs / ghostTimeMs) is a least-squares projection onto
   {1, cos, sin} at f0. The GHOST window (15 ms) is shorter than one E1 period, so a DFT bin cannot read it.
7. AT-13: the Anchor's mean instantaneous frequency over [1 s, 2 s) comes from phase() differences, using the
   anchorPhaseTap seam on voice 0. Pass requires the follow-ratio tap != 1 and the shift within +-5 cents of
   1200 log2(ratio). Both algorithms run at Amount 1, the spec's setting; P-4 shows both flipped there.
8. AT-17: BH7 single-bin power at f0/2 over 2^16 samples from 1 s, in dB relative to the Sine render's f0 power,
   floored at -60 dB (the Phase 8 relative floor).
9. Note Memory rows (AT-43 ... AT-46). On A_s, an envelope restart from sustain 1 re-attacks from 1 to 1
   (enterAttack starts from output_), so every envelope-only Actions difference is silent. Each row therefore pairs M
   with an M_ref whose resolved Actions differ only in the oscillator restart (phase reset + declick); envelope, Drop
   (amount 0) and Anchor actions are identical. The reading is the core-h1 Goertzel phase jump, |wrap(phi_M - phi_ref)|
   >= 30 deg, at the new f0 over 4 periods from t1 + 20 ms.
     AT-43 AlwaysRetrigger vs EnvelopeRetriggerOnly, Overlap
     AT-44 Legato vs OscillatorContinuous, Tail (note-off 10 ms before t1)
     AT-45 EnvelopeRetriggerOnly vs Legato, Tail
     AT-46 OscillatorContinuous vs AlwaysRetrigger, Tail
   t1 is the grid point in [0.5 s, 0.5 s + one period] whose predicted jump frac(f1 t1 / fs + f2 L_d / fs) is
   closest to half a cycle. M_ref, the transition kind and t1 are written in the CSV's contrast column.
10. Frame-wise rows (AT-33 ... AT-40, SC-009) use S9.11 frames (8 periods, hop 960) from the 1 s settle.
    AT-34 ... AT-38 run CYCLE 0.1 Hz for 30 s. AT-39 runs ENV for 6 s, retriggered every 2 s (note-off at k 2 s,
    note-on 64 samples later, in both arms). AT-40 runs DRIFT for 30 s. AT-33 runs field MOTION for 10 s.
    Frame D_br is the centroid over h1..h8 of the frame fit; frame D_cx is (sum_{n>=2} + P_{>=9}) / P1, floored at
    -60 dB re P1. Each contrast is p2p(on) - p2p(off).
11. FR-009 ampStep (Envelope shard). Each envelope row has a morph arm on A_s: a held note, a 5 ms ramp p 0 -> 1 at
    0.5 s, and endpoints that differ only in the row's field. ampStep is max |dg_amp| over the 64 samples after each
    grid point where that field's resolved value changed (bitwise, grid records), written beside ampStep_ref from
    the no-morph run. It is recorded, not gated. Other rows write n/a.
12. CSVs. Each TEST_CASE writes its own file, evidence/audibility-table/<case>.csv. The [long] shards run as
    concurrent processes in the close lane, so a single audibility-table.csv would be a write race (DEVIATION from
    the task's file name; the close lane can concatenate the files). The other outputs are macro-monotone.csv
    (+ -smoke), motion-mass-swell.txt (+ -smoke) and h17-poly-gr.txt. Each shard writes its CSV before its first
    REQUIRE, so a red cell never loses the rest of the table.
13. H-17 DEVIATION. The engine's pitch API is MIDI notes plus one global bend (C-11), so 4 voices detuned by cents
    around E1 cannot be reached through it. Recorded instead: MONO E1, and POLY 4 voices on E1 / F1 / F#1 / G1, beside
