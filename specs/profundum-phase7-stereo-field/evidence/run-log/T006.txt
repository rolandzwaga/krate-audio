## Decisions / deviations
1. DEVIATION (surface, do not silently revert): the S7.3 decode `outL = M + Sp, outR = M - Sp` is taken only when
   Sp != 0 (compares true for both zeros); a zero Sp writes M to both channels. Reason: with M == -0 (an input pair
   of -0) and Sp == +/-0 the verbatim decode gives -0 + +0 = +0 on one side and -0 on the other, breaking the
   L == R and output == input bit gates (SC-004(b)(c), FR-051) and C-1 (iii); under -ffast-math the compiler may also
   fold M + 0 differently per platform. The numeric behaviour is otherwise identical (M + 0 == M for every non-zero
   M). One compare per sample.
2. The idle transition also runs in the right == left loop, so a mono call leaves sideIdle_ / the crossover in the
   state a stereo call would (S7.3 says both smoothers run there "so their state matches a stereo call").
3. "Seeds 0xB17E and 0x1234 give different outputs": MOTION feeds only the per-voice law (the stage never reads m),
   so the difference is asserted on the emitted vectors of the E1 query.
4. ContinuousControlsNoCrossfade steps the controls cumulatively (each step changes exactly one control), then all
   seven back at once.
5. The Anchor dirty-state record runs at the default controls (SPREAD, 120 Hz, Gravity 0.5) for each of E0/E1/E2/C3.
6. The tasks.md Verify line lists MidBitExact / both DirtyState cases as "expected red until ruled"; with the ruled
   switches (false) they record and are expected green.
